# Database schema — DB-001 initial identity foundation

Migration 0001_identity_foundation creates isolated schema nurpath, three tables and a version marker nurpath_alembic_version in the default schema. Principal UUID is application-owned; provider issuer and subject form a unique external identity mapped to it. Preferences FK ties language to principal; only bn/en/ar/ur allowed. UTC-aware timestamps; explicit app-side update timestamps in later repository code. No passwords or real user data stored here.

All three tables revoke PUBLIC access and enable FORCE ROW LEVEL SECURITY without policies. Ordinary roles must see no rows and cannot insert even if granted table privileges. Database owners with superuser/BYPASSRLS can bypass, so never use such credentials for app traffic. AUTH-001 must introduce least-privilege roles and tested transaction-local principal context before enabling app access. No production role or auth flow configured. Online migration is guarded to loopback disposable CI only, no destructive downgrade. Future Neon deployment requires explicit reviewed branch-target identity and secure migration credentials; Supabase compatibility needs actual rehearsal.
